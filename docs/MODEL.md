## Provenance and reproducibility

`tools/prepare_model.py` (driven by `npm run setup:model`):

1. downloads `config.json`, the checkpoint and `vocab.txt` at the pinned
   revision and checks each file's sha256 against `tools/model_lock.json`;
2. loads the encoder with `transformers` and **fails** if any encoder tensor
   is missing or has the wrong shape (the original `export_model.py` silently
   fell back to random weights);
3. checks the architecture (absolute positions, exact GELU) against the lock;
4. writes the CSWT file: a 44-byte header (magic, format version,
   dimensions, LayerNorm ε, dtype) followed by float32 tensors in a fixed
   order, with linear weights transposed to `[in, out]`;
5. verifies the parameter count and that the export's sha256 equals the
   pinned value (the export is byte-for-byte deterministic);
6. writes `model.json` with metadata and self-test reference embeddings
   computed by PyTorch.

Python dependencies are hash-locked (`tools/requirements.lock`, CPU-only
PyTorch). The Rust parser (`src/weights.rs`) re-validates the header and the
exact payload length and rejects NaN/Inf values, so a truncated or foreign
file is an error, never a silently wrong model.

## Correctness against the reference

`tools/parity.py` compares the Rust implementation with Hugging Face
`tokenizers` (`BertWordPieceTokenizer`, cross-checked against
`AutoTokenizer` where the repo ships one) and `transformers` `BertModel` on 24
adversarial inputs (empty strings, Turkish, accents, CJK, emoji, control
characters, a 101-character word, >128 tokens):

| | Token-id mismatches | max \|Δ embedding\| | min cosine |
|---|---|---|---|
| bert-tiny | 0 / 24 | 1.2 × 10⁻⁷ | 0.99999988 |
| all-MiniLM-L6-v2 | 0 / 24 | 3.0 × 10⁻⁷ | 0.99999988 |
| *original prototype tokenizer* | **10 / 24** | — | — |

The original tokenizer failed on all Turkish sentences with ç/ğ/ş/ü,
precomposed accents (no NFD decomposition before stripping marks),
Greek/Cyrillic capitals, CJK and words over 100 characters. It was also
rebuilt (30,522-entry hash map) for every batch. The original encoder used
Burn's default LayerNorm ε = 1e-5 instead of BERT's 1e-12 (effect measured:
max |Δ| 1.6 × 10⁻⁴ — real but negligible).

Fixtures generated by `parity.py` are committed under `tests/fixtures/` and
enforced by `cargo test` (`tests/parity.rs`); CI requires the model-dependent
test to run. On GPU, `tests/gpu_parity.rs` (manual, needs a GPU) measured
max |Δ| 3.8 × 10⁻⁷ against PyTorch with native wgpu, and the in-browser WebGPU
backend reproduced the CPU scores to ~1 × 10⁻⁷ on an NVIDIA Ampere GPU.

## Evaluation

Full generated report: [`docs/evaluation/RESULTS.md`](evaluation/RESULTS.md)
(`node scripts/evaluate.ts`, embeddings from the shipped Rust code, decisions
from the shipped `decide()` function).

**Dataset** (`eval/dataset.jsonl`, `eval/topics.json`): 318 short texts
(208 English, 110 Turkish) across 8 topics — cryptocurrency, movie/TV
spoilers, politics, sports, video games, technology, health/fitness and
finance — plus neutral texts, 30 *hard negatives* built around lexical traps
("the crypt beneath the cathedral", "chicken stock", "birthday party") and 12
multi-label items. Positives include "hard" items with no topic keyword
("Lost my seed phrase…"). 33 topic phrasings (2–3 per topic and language).
Labels were assigned by the author from the text content before any model
was run. **Limitations:** single annotator, synthetic news/social-style
sentences written for this purpose, no UI strings, small Turkish set.

**Method.** Unit = (topic phrasing, text) pair in the same language. The
dataset is split 50/50 by a hash of the item id. Thresholds are chosen on the
English calibration half only, maximising F0.5 (precise), F1 (balanced) or
F2 (thorough) for the hybrid classifier; all numbers below are on the held-out
test half.

**English, test split, hybrid (shipped) classifier**

| Model | Mode | Threshold | Precision | Recall | F1 | FPR |
|---|---|---|---|---|---|---|
| all-MiniLM-L6-v2 | precise | 0.175 | 74.5% | 55.4% | 63.6% | 2.2% |
| all-MiniLM-L6-v2 | balanced | 0.135 | 65.2% | 70.1% | **67.5%** | 4.4% |
| all-MiniLM-L6-v2 | thorough | 0.115 | 54.4% | 76.6% | 63.7% | 7.5% |
| paraphrase-MiniLM-L3-v2 | balanced | 0.19 | 60.8% | 56.5% | 58.6% | 4.3% |
| bert-tiny | balanced | 0.665 | 31.3% | 55.4% | 40.0% | 14.3% |
| keywords only (lexical) | balanced | — | 100% | 1.1% | 2.2% | 0.0% |

Threshold-free ranking quality (ROC-AUC, English): MiniLM-L6 0.922,
MiniLM-L3 0.918, bert-tiny 0.766. For bert-tiny, matching and non-matching
pairs have mean cosine 0.689 vs 0.644 — mean-pooled bert-tiny vectors are
too anisotropic for similarity search, which is why the model was replaced.

**Legacy thresholds.** The prototype's 0.68 / 0.62 / 0.56 were never
calibrated. With bert-tiny they flag about half of all unrelated text (54 %
false-positive rate at 0.62, both languages); with MiniLM they would match
almost nothing (MiniLM-L6 recall at 0.62: 1.1 % English) — thresholds must be
model-specific and are now stored per model in `src/shared/models.ts`.

**Turkish.** ROC-AUC 0.52–0.54 for every model, i.e. close to chance; the
English-calibrated balanced threshold gives 86.8 % false positives on Turkish
text for MiniLM-L6. All three encoders are English-only (English WordPiece
vocabulary). ClearScroll therefore documents English as the supported
language; keyword rules (accent-insensitive) still work for any language.
A multilingual encoder (e.g. paraphrase-multilingual-MiniLM-L12-v2) needs a
SentencePiece tokenizer and a 250k-token embedding table (~470 MB float32)
and was not adopted.

**Topic phrasing.** Prefixing topics with a template ("This text is about
{topic}.") lowered F1 for all three models and is not used. Concrete topics
work better than broad ones: "Real Madrid beat Barcelona 3-1…" scores 0.133
for "sports" (below threshold) but 0.187 for "football" and 0.277 for
"soccer".

## Known failure modes

* Short UI strings receive inflated similarity: "Home & Garden · 3 min read"
  scores 0.182 against "football" and is blurred in balanced mode. Texts
  shorter than 30 / 24 / 16 characters (precise / balanced / thorough) are
  excluded from semantic matching for this reason, but longer labels can still
  match. Mitigation: add such regions as protected selectors. The evaluation
  set contains no UI strings yet.
* Domain knowledge is limited: "Solana validators reported another outage…"
  scores 0.049 for "cryptocurrency" and is missed.
* Keyword fallback only catches literal mentions (recall ≈ 1–6 %).

## Performance trade-offs

Measured in Chromium 156 on an i7-11800H (details: `docs/BENCHMARKS.md`):

| Model | Package | WASM memory | CPU ms/text (batch 24) | WebGPU ms/text | EN F1 |
|---|---|---|---|---|---|
| all-MiniLM-L6-v2 | 97 MiB | 219 MiB | 27.7 | 2.6 (NVIDIA Ampere) | 67.5% |
| paraphrase-MiniLM-L3-v2 | 77 MiB | 179 MiB | 13.7 | not measured | 58.6% |
| bert-tiny | 28 MiB | 51 MiB | 1.7 | not measured | 40.0% |

MiniLM-L6 is the default because quality dominates the product: at a 4–5 %
false-positive rate it finds 70 % of related English texts, while bert-tiny's
best balanced setting blurs one in seven unrelated texts.

## Updating the model

See `docs/PRODUCTION_RUNBOOK.md#model-update`. In short: add an entry to
`tools/model_lock.json`, run `prepare_model.py --model <id> --update-lock`
(maintainers only; this is trust-on-first-use), regenerate parity fixtures
with `tools/parity.py --write-fixtures`, run `scripts/evaluate.ts`, copy the
calibrated thresholds into `MODEL_PROFILES`, and re-run the full test and
benchmark suites.
